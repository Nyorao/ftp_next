## 0. 先说缺陷和前提风险

1. **多参考片 B 组当前结果为负。** 三种子、固定第 6000 步最终 EMA，B 的平均主 Dice 比 A（纯三片）**低 1.0246pp** [文档称，README]。在弄清楚为什么变差之前，继续加参考片数量风险很大。
2. B 和 A 的差别不只是“多了一张中部片”，还同时改变了融合层：三路 softmax 变成四路 softmax，四路权重初值都是 1/4（A 是 1/3），γ 由四路共享 [已核]。初始化时 γ=0，两者输出都等于目标特征，所以起点相同；但 γ 一旦离开 0，参考路和邻片共用同一个 γ，模型无法只放大邻片而压低参考片（只能靠 softmax 权重调）[推断]。所以 −1.02pp 不能直接归因于“中部片信息有害”，也可能是融合方式的问题。这是我的推断，需要 B 的诊断结果（γ、w、`reference_zero` / `other_case` / `same_case_random`）来判断。
3. **文本路线到目前为止没有一组通过预设筛查** [文档称]。其中证据最好的是 N7（E2 词 token + E3 CLS、监督式组织路由、差分融合）：200 轮配对训练中，最佳验证主 Dice 比 N0 **高 0.8635pp**，但 union-present **低 0.3750pp**，按双指标规则未通过 [文档称，README]。N7 本身已经是像素级的文本引导，所以模块二最自然的起点是 N7，而不是从零设计。
4. 两个模块都建立在三片 adaptive 骨干上，而这个骨干自身也没通过确认：6000 步 +0.5646pp，三种子 30000 步平均 +0.4313pp，但平均 union-present 下降 [文档称，`docs/context_architecture_efficiency_20261106.md`]。三个结果有一个共同现象：**主 Dice 上升时 union-present 下降**，说明缺失类别的误检在增加。这可能是三条路线共同的问题，值得单独查。

## 1. 模块一：多参考片输入（前后邻片 + 中部片）

### 1.1 现有实现：病例上下文 B 组 [已核]

| 项 | 现状 |
|---|---|
| 输入 | `[i−1, i, i+1, floor((N−1)/2)]`，4 通道；越界复制端点；参考片即使与局部片重复也保留 |
| 编码 | 四片共享同一编码器（32/64/128/256/256），参考片没有独立分支 |
| 融合位置 | stride 4/8/16（通道 128/256/256）；stride 1/2 跳接只取目标片 |
| 融合公式 | `w = softmax(Conv1x1(4C→4))`，`F = F0 + γ(Σ w_j F_j − F0)`；权重卷积零初始化，γ 每尺度一个、初值 0、无约束 |
| 参数增量 | 单个学生 +4,483（5,693,123 vs A 的 5,688,640） |
| 监督 | 只监督目标片，参考片标签不读取 |
| 增强 | 四片共享空间增强；参考片强度扰动用独立种子偏移 600000101；CutMix 混合所有通道 |
| 推理 | 整卷缓存，参考片预编码一次，跨输出窗口复用 |
| C 组（对照） | 不加参考片，改给三片 logits 加相对位置偏置（+249 参数），与 B 互斥 |
| 补充诊断 | B 的第四槽替换为置零 / 其他病例中部片 / 同病例随机片，各 3 个随机种子；γ、w、`γ·wr·(Fr−F0)` 的残差比例 |

## 2. 模块二：文本像素级特征引导

以下除标注 [已核] / [文档称] 的部分外，全部是提案或问题。

### 2.1 仓库里已有的文本接入（全部未通过筛查）

| 方案 | 注入位置 | 结果 |
|---|---|---|
| 外部组织提示教师 | 不进网络，生成额外伪标签 | 80.2212% vs 基线 80.3505% [文档称] |
| 内部文本（单点） | CRF4 之后、D3 之前（14×14） | 组织文本 80.2298%，中性 80.2538%，基线 80.3505% [文档称] |
| 分层文本 | CRF4→D3、D3→D2、D2→D1（14/28/56） | 80.4696% vs 基线 80.3505%，+0.12pp，union 下降 [文档称] |
| **N7 双层编码器文本** | 编码器 E2（词 token）+ E3（CLS），三片共享 | 200 轮：主 Dice +0.8635pp，union −0.375pp [文档称] |

N7 的关键机制 [已核，`experiments/DUAL_TEXT_SCREEN.md`、`freqssl/dual_text.py`]：
- 冻结 BiomedCLIP 文本库：第 12 层词 token、每类 CLS、4 个 512 维组织锚点，存进 checkpoint，推理不需要文本编码器。
- “aligned routing”：512 维归一化**逐像素投影**与组织锚点算相似度（温度 0.07），同一组 logits 同时用于类别混合和面积池化、类别平衡的组织 CE（辅助损失系数 0.1）。
- 差分融合：`tanh(g)·(Φ(Q,Z) − Φ(Q,0))`，门初值 0。
- E2/E3 在编码器内部、跳接保存之前修改特征。按 widths 的索引，E2 对应 stride 4（56×56），E3 对应 stride 8 [推断]。

也就是说，**“像素级文本引导”在仓库里已经有一个实现（N7），而且是文本路线里唯一明显提升主 Dice 的。** 它的问题是 union-present 下降。

### 2.3 候选方向 [提案]

1. **在 N7 基础上处理 union 下降**
   - 先定位 union 下降来自哪些类别：用现有 `union_decomposition.csv` 的格式（K 个 GT 存在类、M 个误检类）分解 N7 与 N0 的差。
   - 若误检集中在编号类：文本只有组织语义，可能让模型更自信地预测组织但编号出错。可试把文本只作用于组织判别、编号仍由视觉决定（例如只调制组织相关通道）。
   - 若误检集中在视野边缘或端点片：可能和三片骨干的共同问题有关（见 0.4），而不是文本造成的。
2. **把 N7 的逐像素组织相似度图作为解码器的空间先验**
   - 现在相似度 logits 只用于编码器内部的混合和辅助损失。可以把它上采样后作为解码器各级的门控或 FiLM 条件。
   - 风险：分层文本的组织注意力图前景 Dice 只有 4–8% [文档称]，N7 的图质量未知，需先测其对组织 GT 的 Dice。
3. **文本引导 + 参考片联合**
   - 中部参考片经同一文本路由得到组织相似度图，作为模块一的额外条件。
   - 风险：两个尚未单独通过的模块叠加，结果无法归因。只应在两个模块各自通过后再做。
